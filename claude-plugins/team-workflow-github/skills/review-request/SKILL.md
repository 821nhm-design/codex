# レビュー依頼（プルリクエスト作成）

対象リポジトリは特に指定がなければ `821nhm-design/codex`。

## 手順

1. 対象のブランチと、関係するIssue番号を確認する。分からなければユーザーに聞く。
2. ブランチとmainの差分を読み、変更点を3〜5行で要約する。
3. 下書きをチャットに表示する。

   ```
   タイトル: …
   ---
   ## 何を変えたか
   - …
   ## 確認してほしいところ
   - 見た目：…
   - 正確さ（表記・価格・リンク）：…
   ## 関連Issue
   Closes #…
   ```

4. ユーザーが明確に了承してから、**下書き（Draft）** としてプルリクエストを作る。レビュアーの指定はユーザーが名前を挙げた人だけにする。
5. 作成後、PRの番号とリンクを1行で伝える。

## 絶対にしないこと

- マージ、mainへの直接push、force push
- ブランチ・ファイル・Issueの削除
- リリース作成、サイト公開、出品、決済設定の変更
- 差分に含まれる個人情報や鍵（APIキー・トークン）をPR本文に書くこと。見つけたら作業を止め、ユーザーに知らせる。
